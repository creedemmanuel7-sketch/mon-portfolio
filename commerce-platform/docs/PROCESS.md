# Processus projet — CredoShop

Aligné sur le cycle Design → Dev → QA → Deploy.

## 1. Rôles

| Acteur | Objectif | Sur ce projet (solo portfolio) |
|--------|----------|--------------------------------|
| **UX Designer** | Besoin, parcours, wireframes | Étape 1 — docs + wireframes HTML |
| **UI Designer** | Look & feel, design system | Étape 2 — maquettes haute fidélité |
| **Product Owner** | Prioriser le MVP | Crédo (toi) + agent |
| **Frontend Dev** | UI fidèle aux maquettes | Étape 3 |
| **Backend Dev** | Métier, data, API, sécurité | Étape 3 |
| **DevOps** | CI/CD, prod | Étape 5 |
| **QA Fonctionnel** | Plans de test, cas limites | Étape 3 (rédaction) + Étape 4 |
| **QA Auto** | Régression / smoke | Étape 4–5 (smoke prod) |

En mode portfolio solo, **un même intervenant** enchaîne les casquettes — d’où l’importance des docs écrites à chaque étape.

## 2. Étapes

### Étape 1 — Cadrage & UX *(actuelle)*
- Clarifier le besoin et le MVP
- Personas + user stories
- User flows
- Specs fonctionnelles
- Wireframes basse fidélité
- Note de faisabilité (stack)

### Étape 2 — Design UI & Prototypage
- Design system (couleurs, type, composants)
- Maquettes HD des écrans MVP
- Prototype cliquable
- Revue effort d’intégration

### Étape 3 — Développement
- Setup repo / environnements
- Front + back + Stripe test
- Tests unitaires / cas de test QA
- Staging

### Étape 4 — Qualification
- Exécution des scénarios
- Bugs → correctifs → retest
- Design QA (visuel)

### Étape 5 — Déploiement
- Prod + migrations data
- Smoke tests
- Lien depuis le portfolio Crédo.ai
